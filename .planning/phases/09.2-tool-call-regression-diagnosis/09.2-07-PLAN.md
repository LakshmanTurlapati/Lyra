<objective>
Rebalance the training dataset to fix the three coupled H1 pathologies identified in D06-TRAINING-AUDIT.md, using **parallel Claude Code subagents** (not Anthropic SDK / Batch API — project has no API key):

1. **pct_end_in_tool_call = 0.00%** → target ≥ 5% (generate ≥500 single-turn samples that END in `<tool_call>`)
2. **top-5 canned-suffix coverage = 46%** → target ≤ 20% (expand ending-phrase pool 5 → 30+ variants, regenerate ~30% of multi-turn samples)
3. **tool-calling domain fraction = 90.22%** → target ≤ 80% (generate ~800 code + ~800 knowledge supplementary samples)

Each generation wave spawns N parallel subagents via the `Agent` tool. Each subagent receives a prompt spec + target count + output file path, writes ShareGPT JSONL directly, returns a compact confirmation. The orchestrator collects outputs, validates schemas, runs curation, reassembles the HF dataset, verifies thresholds via pytest.

This plan produces the dataset that Plan 06A consumes.
</objective>

<subagent_architecture>
**Why subagents instead of SDK calls:**
- No ANTHROPIC_API_KEY needed — subagents run within the Claude Code harness
- Each subagent is itself a Claude instance (Sonnet 4.6 default — cost-efficient and capable for synthetic data)
- Parallel dispatch via a single orchestrator message with multiple Agent tool calls
- Each subagent writes its JSONL output directly to disk (worktree-isolated)
- Orchestrator merges outputs after wave completes

**Parallelism budget per wave:** 8-10 subagents. This is safe under the user's "no parallel model evals" constraint because subagents generate TEXT via Claude API — they do NOT load PyTorch models locally. The 64GB-host crash risk does NOT apply.

**Subagent contract per generation task:**
- Inputs: prompt spec, target sample count, output file path, ShareGPT schema reminder
- Outputs: JSONL file on disk (one ShareGPT conversation per line) + short confirmation message
- Constraints: subagent MUST NOT invoke `scripts/eval_inference`, training, or anything that loads a local model; MUST validate its own output against the schema before writing
</subagent_architecture>
</context>

<task id="2" name="Wave B — Single-turn tool-call-ending samples (10 parallel subagents, ≥500 samples)" type="execute" gate="blocking">

**Goal:** Generate ≥ 500 ShareGPT samples where the assistant's FINAL turn ends with a `<tool_call>` — not text. Directly addresses the 0.00% `pct_end_in_tool_call` pathology.

**Dispatch:** 10 parallel `Agent` calls, each producing 50 samples. Each subagent's prompt:

> Generate exactly 50 single-turn ShareGPT conversations. Each conversation must have exactly 3 messages: system, user, assistant. The assistant's content must be "" (empty string) and have a populated `tool_calls` field. Example schema:
> ```json
> {"messages": [{"role":"system","content":"You are a helpful assistant with tools."},{"role":"user","content":"Check the weather in Paris."},{"role":"assistant","content":"","tool_calls":[{"type":"function","function":{"name":"get_weather","arguments":{"city":"Paris"}}}]}], "tools":[{"type":"function","function":{"name":"get_weather","description":"...","parameters":{...}}}], "domain":"tool-calling"}
> ```
> Diversity requirements:
> - ≥ 20 unique tool names across your 50 samples (get_weather, send_email, search_web, create_calendar_event, git_commit, read_file, query_database, etc.)
> - ≥ 3 unique argument value per tool (e.g. 3 different cities for get_weather)
> - User phrasing diversity: direct/imperative/question/conversational
> - NO canned phrases — vary surface form
> Write results to `datasets/tool-calling/v2-single-turn/batch-{SUBAGENT_ID}.jsonl` (one JSON per line).
> Subagent ID for this call: **{pass unique 01..10}**

Subagents 01-10 get ids 01 through 10. Run in parallel via a single orchestrator message with 10 Agent calls.

**Acceptance:**
- 10 files at `datasets/tool-calling/v2-single-turn/batch-01.jsonl` through `batch-10.jsonl`
- Each file has exactly 50 lines, each a valid ShareGPT conversation ending in tool_call
