## What Worked

1. **Halved learning rate** prevented the ultra-low-loss memorization signature v2 exhibited. Final loss 0.8027 is in a healthy regularization range — model learned patterns rather than memorizing samples.
2. **30-variant suffix pool** (Plan 09.2-07) diversified the canned-suffix cluster that was likely mode-collapsing v2's tool-call generation.
3. **500 single-turn tool-call-ending samples** (Plan 09.2-07) taught the model to terminate with `<tool_call>...</tool_call>` rather than always wrapping with prose.
4. **Domain rebalancing** (79.8% tool-call vs v2's 90.2%) gave code and knowledge enough training signal that code-syntax actually surged, and MMLU stayed within 3% of base.
5. **Sequential main-repo dispatch** honored the architectural constraint — no gitignored artifacts lost in a worktree, no parallel-eval memory blowup.

## What Did Not Work

1. **Tool-call-format did not clear base.** The 0.2096 result is a 3.3× improvement over v2 but still 51.5% below base. Hypothesis: the rebalancing addressed the mode-collapse symptom (per 09.2-07 thresholds all met) but did not fully restore the base model's latent tool-use capability, which fine-tuning appears to actively erode — possibly because even at 79.8% tool-call weight, the distributional shift from base's instruction-diversity training is destructive to that specific capability.
2. **Canned-suffix coverage reduction alone was insufficient.** DIAGNOSIS.md predicted <50% success probability even with the rebalance. 0.2096 / 0.4065 = 51.6% of base performance recovered, right at that prediction boundary. The research was correct.

### Option 1 — v4 retrain with a new hypothesis

**Cost:** ~4-5 h sequential (similar to this run) + fresh diagnosis + possibly another data-rework plan.

**Candidate hypotheses not yet tested:**
- **H2: Higher tool-call weight with stronger regularization.** Go back to ~90% tool-call fraction (like v2) but keep the halved lr + single epoch + diverse suffixes. Tests whether domain rebalancing was the wrong lever.
- **H3: Even lower lr (e.g., 1e-5) with 2-3 epochs.** Very gentle fine-tuning — maximizes signal retention from base. Tests whether the issue is fine-tuning aggressiveness, not data.
- **H4: Instruction-diversity augmentation.** Add ~2,000 non-tool-call instruction-following samples (general conversational) to dilute the tool-call focus further. Tests whether base's instruction-diversity is load-bearing for tool-call-format specifically.
- **H5: Adapter-only release, no merge.** Ship the 72 MB adapter as the release artifact; users apply it to base at inference time. Runtime decides whether to use the adapter per prompt. Tests a completely different release shape.

**Risk:** Another round without clearing D-09. Multiple v4 attempts may be needed. No guarantee the ceiling isn't ~0.25.
