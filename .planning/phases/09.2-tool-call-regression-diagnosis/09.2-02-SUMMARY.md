# Phase 09.2 Plan 02: D-04 Template Parity Test Summary

Turn the Phase 09.2 Plan 01 RED stub into two GREEN pytest assertions that lock the Phase 09.1 template-persistence fix as a permanent regression test, conclusively ruling out H5 from the 09.2 hypothesis ranking with CI-level evidence.

## What Was Built

`tests/test_phase_09_2/test_template_parity.py` now contains two concrete pytest functions (76 lines total, up from 27 in the RED stub):

1. `test_stripped_train_template_matches_persisted_template` — asserts that the train-time chat template from `scripts/train.py` lines 436-456 (provided by the `train_template_string` fixture), with the TRL `{% generation %}` and `{% endgeneration %}` markers stripped, is byte-identical to the `chat_template` field persisted in `models/lyra-merged/tokenizer_config.json` (provided by the `persisted_template_string` fixture).

2. `test_both_templates_produce_identical_token_ids` — loads `AutoTokenizer.from_pretrained("models/lyra-merged")`, renders the canonical `[system, user]` weather-query prompt (`canonical_tool_call_prompt` fixture) twice — once with each template assigned to `tok.chat_template` — via `apply_chat_template(..., tokenize=False, add_generation_prompt=True)`, and asserts `list[int]` equality on the resulting `input_ids`. A mismatch triggers `pytest.fail` with a precise first-diff index and a 5-token window of each side for diagnostic context.

Both tests run without loading model weights (tokenizer-only), satisfying the user's sequential-eval constraint (D-11 / memory-safety).

## Hypothesis Status After This Plan

**H5 (chat-template persistence bug) — ruled out with CI-level evidence.**

Research (09.2-RESEARCH.md §Ranked Hypothesis List) had already empirically demonstrated on 5 consecutive test samples that both templates yield identical token IDs. This plan converts that ad-hoc empirical finding into a permanent `pytest` that runs in the regression suite, so any future `scripts/train.py` edit that desyncs the in-memory template from the persisted template fails CI rather than silently regressing the eval pipeline (which was the entire point of the Phase 09.1 Plan 01 template-persistence fix).

**Template mechanics cannot be the root cause of the Phase 09.1 tool-call-format regression.** Plan 05's DIAGNOSIS.md must attribute the regression to data-distribution / training-distribution pathologies (H1: mode collapse onto canned suffix templates + 90.2% domain skew) or to metric-methodology artifacts (H3: 94% of test labels expect text, not tool-calls). H2 (assistant_only_loss mask interaction with `<tool_call>` tokens) remains open; D-04 parity does NOT rule it out because the loss mask is computed from the train-time template (with markers) and is invariant to the persisted template — the mask could still skip tool_call tokens even though tokenization matches.
