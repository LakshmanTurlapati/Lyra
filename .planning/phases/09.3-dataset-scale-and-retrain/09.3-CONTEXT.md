# Phase 09.3: Dataset Scale + Continue-Train v5 - Context

**Gathered:** 2026-04-24
**Status:** Ready for planning
**Budget:** ~$1,100 Anthropic Batch API + ~2-3 days wall-clock
**Trigger:** Phase 09.2-06 Branch 06A completed; v4 landed at tool-call-format 0.4044 (base 0.4065, delta −0.5%, strict D-09 FAIL, parity within noise). User explicitly rejected accept-partial and approved dataset-scale continue-train pipeline.

<domain>
## Phase Boundary

Deliver a Lyra v5 model that STRICTLY beats base SmolLM2-1.7B-Instruct's 0.4065 on tool-call-format while staying within 5% on MMLU/ARC/HellaSwag, by (1) generating ~42K additional rebalanced training samples that apply 09.2-07's mode-collapse-avoiding rules at scale, (2) reassembling with the existing 7,519-sample rebalanced dataset into a ~50K DatasetDict, and (3) continue-training v5 from v4's LoRA adapter (not from base) for 1 epoch on the new data.

**Out of scope for Phase 09.3:**
- Further hyperparameter sweeps beyond lr=1e-5 × 1 epoch
- New eval benchmarks beyond the existing MMLU/ARC/HellaSwag + custom tool-call-format/code-syntax suite
- Shipping artifacts — Phase 09.3 only produces weights + eval numbers; Phase 10 ships
- Experimenting with non-LoRA fine-tuning methods

**Exit conditions (strict):**
- **PASS:** v5 tool-call-format > 0.4065 AND knowledge benchmarks within 5% of base → unblock Phase 10 Waves 2/3 and mark D-06 satisfied
- **FAIL at parity:** v5 tool-call-format 0.40-0.41 (within noise of base) → escalate to user; default recommendation is Option 3 (accept-partial ship of v4 or v5, whichever is better on aggregate)
- **FAIL below parity:** v5 tool-call-format < 0.40 → something went wrong; halt for diagnosis

</domain>

<decisions>
## Implementation Decisions

### Scale & Budget

- **D-01:** Target total dataset size ~50K (42K new + existing 7,519 rebalanced = 49,519 pre-curation; expect ~40-45K post-dedup/filter at typical retention 80-90%).
- **D-02:** Data generation mechanism is **Anthropic Batch API** (Opus batch pricing, 50% batch discount, prompt caching on system prompts). Claude Code subagents (Plan 09.2-07's pattern) do NOT scale to 42K — they produced ~3,500 new samples there. OpenAI is ruled out by project constraints.
- **D-03:** Hard budget cap **$1,500** for Phase 09.3 API spend. Pre-submission token forecast required before each batch. If forecast exceeds $1,500, halt and escalate.
- **D-04:** Total wall-clock cap **3 days elapsed** from Plan 09.3-01 start. If the 24h batch window slips past 48h or training+eval slips past 72h, escalate.

### Data Mix (applies 09.2-07 rebalance rules at scale)

- **D-05:** Domain split at the 42K generation level:
  - **80% tool-call** = 33,600 samples
  - **10% code** = 4,200 samples
  - **10% knowledge** = 4,200 samples
  - Final assembled split must meet D06-TRAINING-AUDIT.md thresholds: tool-call domain fraction ≤ 0.80 post-curation.
- **D-06:** Tool-call sub-mix (within the 33,600):
  - **≥15% single-turn tool-call-ending** (≥5,040 samples) with assistant turn = `<tool_call>...</tool_call>` only (no trailing summary). This is the specific pattern Plan 09.2-07 used 500 samples for; scaling to 5K reinforces it.
  - **Multi-turn with diverse endings** for the remainder, using the full **30-variant suffix pool** (same as 09.2-07). No sample may share its trailing suffix with >5% of other multi-turn samples — enforced at curation.
  - **Function call shape diversity:** at least 40 distinct tool schemas represented across the 33,600 samples, no single schema >5% of the split. Matches Phase 4's 64-schema pool as the reference diversity target.
- **D-07:** Knowledge topic pool expansion REQUIRED. Plan 09.1-04 hit template-pool exhaustion at ~650 knowledge samples with the existing 192-topic pool. Scaling to 4,200 knowledge samples demands pool expansion to **≥600 topics** covering science, history, math, tech, everyday life, arts/humanities, and current events. Plan 09.3-01 owns this expansion.
- **D-08:** Code sub-mix stays proportional to Phase 5's existing 50% utility / 25% file-ops / 25% debugging ratio. 4,200 samples = 2,100 utility / 1,050 file-ops / 1,050 debugging. No canned templates — each sample pulls from language pools per Phase 5 convention.

### Training Strategy

- **D-09:** v5 is trained via **continue-training from v4's LoRA adapter** (path: `models/lyra-adapter/adapter_model.safetensors` as of commit `1ba6b48`; v4 overwrote v3, so the current on-disk adapter IS v4). Base weights stay frozen; the existing v4 LoRA adapter is the starting point and new gradient updates accumulate on top.
  - **Novel step:** `scripts/train.py` currently loads base + starts LoRA from scratch. Plan 09.3-03 must verify/patch it to support `--resume-from-adapter <path>` or equivalent. PEFT supports this natively via `PeftModel.from_pretrained(base, adapter_path, is_trainable=True)` — should be a small patch.
  - If continue-training turns out to be infeasible, the fallback is retraining from base on the full 50K dataset at lr=1e-5 × 2 epochs (same hyperparams as v4) — costs ~3x more time (~12h training) but known-working.
- **D-10:** Continue-training hyperparameters: **lr=1e-5, epochs=1** on the new 42K rebalanced samples only (NOT the full 50K — v4's adapter already saw the 7,519-sample rebalanced set for 2 epochs). Preserves v4's regularization discipline.
  - Effective total training signal on the rebalanced-rules data: v4 (7,519 × 2 epochs = 15,038 sample-passes) + v5-delta (42,000 × 1 epoch = 42,000 sample-passes) = 57,038 sample-passes. Nearly 4x v4's total, but at the same gentle lr.
  - Risk: at 42,000 new sample-passes the model may drift from v4's parity. Mitigate by monitoring eval_loss on the held-out validation set; if it spikes above v4's 0.9751, halt early.

### Eval Gates

- **D-11:** **Strict D-09:** v5 tool-call-format > 0.4065 (base). v5 at 0.4065 is NOT pass (must be strictly greater).
- **D-12:** D-10 held: MMLU within 5% of base's 0.5012, ARC within 5% of 0.45, HellaSwag within 5% of 0.66. v4 satisfies all three; v5 expected to maintain.
- **D-13:** Bonus metric: code-syntax. v4 landed 0.4861 (+143% over base's 0.20). v5 should maintain code-syntax ≥ 0.40 (soft target, not a gate). If code-syntax regresses below 0.30, that's a sign the continue-train is eroding the v4 gains — halt and diagnose.

### Escalation Rules

- **D-14:** If v5 fails strict D-09 (lands at parity or below) → HALT this phase. Do NOT auto-launch a v6 retrain. Surface the result to the user with three options:
  - A) Run one more hypothesis (requires explicit user approval of cost + strategy — e.g., H4 instruction-diversity augmentation, H2 re-raise tool-call weight)
  - B) Accept-partial ship (v4 or v5 whichever is better on aggregate) — amend Phase 10 D-06 to accept parity as the gate
  - C) Pivot to 06C (revert-to-base ship) — previously rejected but remains available
- **D-15:** If the 24h Batch API window extends past 48h or any single batch exceeds $500 forecast → halt Plan 09.3-01 and escalate. Real API spend without user approval cap violation.

### Artifact Preservation

- **D-16:** v4's eval JSONs are committed (`results/lyra_v4_*.json` at commit `0de4f53`). v4's safetensors are gitignored but preserved on-disk. Before v5 training overwrites `models/lyra-merged/` and `models/lyra-adapter/`, **snapshot v4 to `/tmp/lyra-v4-snapshot/`** as an insurance backup for 72h. Do NOT commit the snapshot (3.4 GB, gitignored anyway).
- **D-17:** v3 snapshots were not preserved (v3 was overwritten by v4). For v5, the snapshot rule above applies to v4 only. If v5 is strictly better than v4 and ships, v4 snapshot can be discarded.

### Claude's Discretion

- Exact prompt templates for the 42K Batch API generation (Plan 09.3-01 constructs these from existing `prompts/` library)
- Whether to split the 42K into one big batch or multiple smaller batches (depends on Anthropic API batch size limits — 100K messages per batch is the documented cap, so one batch works, but multi-batch offers early abort if first one shows quality issues)
- Exact seed strategy for generation reproducibility (Phase 4/5/6 convention: `batch * 100 + category_offset`)
- Curation threshold tuning (if the new 42K has a different statistical profile than 09.2-07's samples, thresholds may need ±0.02 adjustment — document any deviation in Plan 09.3-02 SUMMARY)
- Whether to re-generate knowledge topic pool from scratch or layer on top of existing 192 topics (recommend: extend, don't replace, to preserve continuity with 09.1)

</decisions>

<specifics>
## Specific Ideas

- **Don't regenerate the 7,519 rebalanced samples** — they're high quality and expensive-in-human-thought to reproduce. Merge, don't replace.
- **Cache the knowledge topic pool expansion.** 09.1-04 hit the ceiling at 650; if we expand to 600+ topics once, it's a permanent repo asset, not a per-phase task.
- **Track per-batch quality stats inline** — if batch 1 of tool-call generation shows canned-suffix clustering despite the prompt discipline, abort before submitting batches 2-N and fix the prompt first. The 50% batch discount is still real on a single batch.
- **v4's code-syntax win (0.4861) is a project asset.** If v5 regresses code-syntax below 0.40, that's a real cost to weigh against any tool-call-format improvement. Not just a "maintain D-10" check.
- **The 3-day wall-clock cap matters** — if Plan 09.3-01 batch extends past 48h (Anthropic batch SLA is 24h but can slip), halt and reconsider strategy. Don't let the phase drag for a week.

</specifics>

## Deferred Ideas

- **H2 (re-raise tool-call weight above 80%)** — ruled out for Phase 09.3; would contradict 09.2-07's rebalancing. Available as a v6 hypothesis if v5 fails strict D-09 per D-14.
- **H4 (+2K general instruction-following samples)** — ruled out for Phase 09.3 as a secondary hypothesis to test after scale; available as a v6 lever.
- **H5 (adapter-only release)** — orthogonal packaging choice, not a training hypothesis. Could be adopted as the Phase 10 release format regardless of which Lyra version ships (v4, v5, or base-revert).

- **Human-in-the-loop review via Argilla** — not in v1.0 scope (Opus-generates-all constraint), but a logical v2.0 quality lever.
