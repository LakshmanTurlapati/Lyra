### D-06 informational audit (tool-call corpus)

Plan 09.3-02 owns the hard gate against the *assembled* corpus (33,500 + 7,519 09.2-07 samples = ~41K). This is the informational pre-merge audit:

| Metric | Result | D-06 floor | Status |
|---|---|---|---|
| Distinct tool schemas | 1,637 | ≥40 | ✓ |
| Max single-schema share | 0.47% (`send_email`) | ≤5% | ✓ |
| Top-5 multi-turn suffix-opener coverage | 16.80% | <20% | ✓ |
| Single-turn tool-call-ending share | 14.85% (4,975 / 33,500) | ≥15% | ⚠ −50 samples |

The single-turn share is the only metric short of D-06. **Flagged for 09.3-02**: when the 33,500 raw-09.3 tool-call samples merge with the 7,519-sample 09.2-07 corpus (which had ~500 single-turn-ending pure samples already), the assembled rate is expected to exceed 15%. If 09.3-02's audit reports the assembled rate below 15%, a top-up batch can be generated quickly (one subagent, ~50-100 samples, ~10 min).

### D-07 knowledge ceiling removed

`templates/knowledge-topics-v2.yaml` lands with 623 topics across 7 categories (science 120 / math 80 / tech 120 / history 80 / everyday_life 80 / arts_humanities 60 / current_events 60+overflow), each with ≥5 sub-angles, ≥80% multi-angle-friendly. This removes the 09.1-04 ceiling that had capped knowledge generation at ~650 samples.

### Pivot from Anthropic Batch API to subagent batches

The original 09.3-01 plan body specified the Anthropic Batch API as the generation mechanism, with budget caps ($500/batch, $1,500 phase), a `scripts/gen_batch_09_3.py` SDK wrapper, a `BATCH-IDS.json` idempotency ledger, and three human checkpoints gating SDK `.create()` calls. Mid-plan, the user redirected: *"listen no api calls.. you generate them in order as batches of multiple sub agents"* (recorded in commit `2196eb7 docs(09.3): swap data generation from Anthropic Batch API to Claude Code subagent batches per user direction`).

Outcome of the pivot:
- **Cost**: $0 instead of the forecasted ~$693 (worst case ~$2,109 per RESEARCH.md)
- **Latency**: ~3-4 days active generation time instead of 24h Batch API SLA × multiple submissions
- **Reproducibility**: every JSONL is bit-reproducible from its generator script (no external service dependency)
- **Cancelled artifacts**: `scripts/gen_batch_09_3.py`, `BATCH-IDS.json`, `tests/test_batch_generation.py`, `tests/test_knowledge_pool.py`, `tests/test_continue_train.py`, `anthropic_batch_fixture` in conftest, and the `anthropic>=0.97.0` requirements.txt entry — none were ever created. The `Conversation.model_validate()` Pydantic gate runs at 09.3-02's curate step instead of inside a Wave 0 test fixture.

### Git LFS for raw phase data (best-practices closeout)

Pre-09.3-01: `datasets/**/*.jsonl` was gitignored; batches 01-06 were force-added inline to git history (~7MB bloat in the regular git objects).

Post-09.3-01: `.gitattributes` now scopes `datasets/*/raw-*/**/*.jsonl` to LFS, and `.gitignore` adds the negation rule `!datasets/*/raw-*/**/*.jsonl`. Batches 07-13 (tool-call), 08-14 (code), and 08-14 (knowledge) — 73 files totalling ~35MB — flow through LFS via 69 LFS objects. LFS does not apply retroactively to batches 01-06 tool-call (those remain inline-tracked); a future `git lfs migrate import` could fold them in if desired, but that rewrites history and is deferred.

## Pivots and Deviations

1. **Batch API → subagent batches** (commit 2196eb7): see above. Plan body retained in git history at f55a2b8^; current PLAN.md is the reconciled subagent-reality version with a `<reconciliation_note>` prologue.

2. **Wave 0 test scaffolding never built**: original plan called for 3 new test files + 1 conftest fixture to gate Wave 0 development. With the SDK out of scope, these became unnecessary — `Conversation.model_validate()` runs at 09.3-02's curate gate.

3. **`requirements.txt` unchanged**: `anthropic>=0.97.0` was never added.

4. **`scripts/generate_knowledge_data.py` unchanged**: original plan called for a `--topic-pool` flag + `load_topic_pool_v2()` function to read the new YAML pool. Since knowledge generation now runs through `scripts/gen_knowledge_09_3_*.py` (which bakes topic data into companion `_data*.py` modules), this patch became unnecessary. Future phases reusing `generate_knowledge_data.py` may still want the flag.

5. **Single-turn share at 14.85% instead of ≥15%**: 50 samples short of D-06's floor. Documented as a 09.3-02 verification point rather than auto-topped-up.
